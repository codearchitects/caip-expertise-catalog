## How the extension uses it

The extension ships a copy of this list and can read this one instead, so the shortlist grows
without an extension release. Point the setting at the raw file:

```jsonc
// settings.json
"caep.expertise.catalogUrl":
  "https://raw.githubusercontent.com/codearchitects/caip-expertise-catalog/main/catalog.json"
```

If the fetch fails, the bundled copy is used and the failure is logged to the CAIP output channel.

Listing a pack here does **not** install it. Installing goes through the extension's own gate,
every time: the pack is staged somewhere disposable, pinned, kept to text only, linted line by
line for prose that tries to direct the agent, shown to the human, and only then written and
recorded in `.caep/expertise.json`. This catalog decides what gets *offered*, not what gets run.

## Layout

```
catalog/<category>/<topic>.json   the source of truth — small files, edited by people
catalog.json                      GENERATED by scripts/build.mjs, read by the extension
schema/topic.schema.json          the shape of a topic file
scripts/build.mjs                 topics → catalog.json (--check in CI)
scripts/refresh.mjs               re-reads stars/forks/licence/branch from the GitHub API
```

`catalog.json` is generated and committed — a raw URL has to serve it with no build step in
between — but it is never hand-edited. CI runs `node scripts/build.mjs --check` and fails when
it disagrees with the topic files.

## Maintaining it

- **People:** see [CONTRIBUTING.md](CONTRIBUTING.md) for the bar an entry must clear, and
  [CATEGORIES.md](CATEGORIES.md) for where things go.
- **AI:** see [AGENTS.md](AGENTS.md). The working procedure for an assistant, and one rule above
  all the others — **it proposes, a human at Code Architects decides**. An assistant works on a
  branch and opens a pull request; it never pushes to `main`, and never approves or merges,
  including its own work.

Two ready-made runs for a Claude Code session in this repository:

```
/catalog-refresh          re-read every entry, propose the factual updates as a PR
/catalog-add <stack>      research a stack, verify candidates, propose the additions as a PR
```

Everything lands as a pull request; `CODEOWNERS` requires a Code Architects review, and `main`
takes no direct pushes.

## Adding something yourself

1. Edit or create `catalog/<category>/<topic>.json` (see the schema).
2. `node scripts/build.mjs`
3. Commit both files, open a pull request with the template filled in.

Or just open an issue — **Propose a pack** — and let somebody else do the paperwork.
